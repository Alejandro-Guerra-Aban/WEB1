## 📌 Convenciones

### Commits

Los cambios se registran mediante mensajes descriptivos.

    feat: añadir ejercicios de programación
    docs: actualizar documentación
    fix: corregir ejercicio
    refactor: reorganizar contenido

### Organización

- Una carpeta por módulo.
- Una carpeta por unidad de trabajo.
- Material separado de ejercicios.
- Prácticas independientes.
- Nombres descriptivos.
- Documentación `README.md` cuando sea necesario.

## 📚 Criterio de documentación

Las prácticas y unidades que necesiten información adicional podrán disponer de su propio `README.md`.

Una documentación estándar podrá seguir esta estructura:

    # Nombre de la práctica

    ## Objetivo

    Descripción del objetivo de la actividad.

    ## Requisitos

    Elementos necesarios para realizarla.

    ## Desarrollo

    Explicación del procedimiento.

    ## Resultado

    Resultado obtenido.

    ## Conclusiones

    Conceptos aprendidos o aspectos relevantes.

---

## 🔧 Convenciones de archivos

Se recomienda utilizar nombres claros y consistentes.

    documentacion.md
    ejercicio-01.md
    practica-01/
    solucion.java
    script.sql
    README.md

Se evitarán nombres ambiguos o poco descriptivos como:

    cosa.txt
    nuevo.txt
    final.txt
    final-final.txt
    prueba2.txt
